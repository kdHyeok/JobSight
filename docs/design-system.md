# 디자인 시스템 — Vibe 참고, 라이트 테마

## 목적

화면을 **미니멀**하게 유지한다. 목록은 핵심만, 나머지는 클릭해서 본다.
monday.com 의 Vibe UI Kit 을 참고했다 — 라이트 서피스, 8px 라운드, 파란 프라이머리, 파스텔 칩.

> Figma 원본 파일은 접근하지 못했다(로그인 필요). 아래 토큰은 Vibe 의 공개된 값과 특징을 옮긴 것이라
> 실제 킷과 다를 수 있다. 색을 맞출 일이 생기면 `main.css` 의 `:root` 한 곳만 고친다.

## 레이아웃 규칙

1. **탑바 3분할** — 왼쪽 브랜드 / 가운데 세그먼트(`채용공고`·`모집 직무`·`기업`·`이력서`·`자기소개`, 홈은 채용공고) / 오른쪽 메뉴 버튼 + 아바타.
   관리자는 성격이 달라 세그먼트에 넣지 않는다. 관리자 계정에게만 보인다.
2. **한 페이지 = 얇은 헤더 + 카드/칸반.** 히어로 문구·설명 단락을 두지 않는다.
   공고 헤더에는 제목과 주 동작만 두고, 관심 공고·진행 중·보관함 개수는 각 탭의 작은 원형 배지에 표시한다.
3. **목록 카드는 핵심만.**
   - 공고: D-day · 모집 부문 · 회사 · 내 상태 · 직무 수
   - 직무: 직무명 · 회사 · D-day
   - 기업: 이름 · 형태 · 업종 2개(+n)
   그 외 필드는 카드에 올리지 않는다. 카드가 길어지면 목록이 아니라 상세가 된다.
   공고 목록은 상태별 칸반이다. 관심 공고는 관심·작성 중, 진행 중은 제출 완료·필기 준비·면접 준비·합격, 보관함은 미지원·서류 탈락·필기 탈락·면접 탈락으로 나눈다.
   카드는 열과 상단 탭에 드롭할 수 있다. 상태 선택 드롭다운은 키보드·터치 대체 조작으로 계속 제공한다.
4. **상세와 수정은 같은 드로어**(`Drawer.vue`, 오른쪽에서 열림)에서 한다.
   카드를 누르면 `보기`, `수정` 을 누르면 같은 자리에서 폼으로 바뀐다. 별도 모달을 띄우지 않는다.
   공고·기업·직무의 읽기 영역을 더블클릭해도 같은 수정 폼을 연다. 버튼·링크·입력·탭과 다른 항목으로 이동하는 행의 더블클릭은 편집 진입으로 가로채지 않는다.
   **동작 버튼(수정·삭제·보관·취소·저장)은 드로어 헤더 바로 아래 한 줄**(`#actions` 슬롯)에 둔다. 하단 푸터 없음.
5. **드로어 안의 종속 데이터는 더블클릭하면 그 데이터의 화면이 열린다.**
   기업 → 채용정보 행 → 공고, 공고 → 모집 직무 행 → 직무. 행은 `<button class="mini-row">` 이고
   `@dblclick` 과 `@keydown.enter` 를 함께 받는다(키보드로도 열려야 한다).
   화면을 넘길 때는 `?focus=<id>` 를 붙인다 — 링크로 공유·북마크된다. 라우팅은 `App.vue` 만 한다.
   **역방향(부모로 가기)은 버튼이다.** 부모는 하나뿐이라 행이 아니라 이름 옆 `.link-button` 을 한 번 눌러 간다:
   공고 → 고용회사, 직무 → 소속 공고.
6. 가운데 모달은 둘뿐이다 — 파괴적 확인(`ConfirmDialog`)과 **첨부 미리보기**(`AttachmentField` 의 `.preview-backdrop`).
   미리보기는 드로어·전체 페이지 어디서 열려도 같아야 하고, 이미지·PDF 를 크게 봐야 해서 예외로 둔다.
7. **규칙 4 의 유일한 예외 — 이력서 편집기는 전체 페이지다.** 섹션 9개·행마다 필드 최대 10개는 520px 드로어에 들어가지 않는다.
   목록은 카드(`/resumes`), 편집기는 `?focus=<id>` 로 같은 보드가 그린다. 섹션은 `.resume-section`, 행은 `.resume-row`(↑↓× 는 `.repeater__move` 재사용).
   저장 안 한 변경은 `변경됨 · 저장 전` 배지 + 이탈 확인.
   지원 직무 선택은 검색창을 눌렀을 때만 열리는 단일 열 드롭다운이다. 입력 아래에 겹쳐 띄우고 최대 높이 안에서만 세로 스크롤한다.
   페이지 전체를 직무 카드로 채우지 않으며 선택한 직무는 칩으로 유지한다. 목록 내부의 휠 스크롤이 페이지로 이어지지 않게 한다.
   자기소개 작성·수정의 연결 이력서도 같은 검색 드롭다운·내부 스크롤·선택 칩 패턴을 쓴다. 검색창의 Enter로 폼이 저장되지 않게 한다.
7. 기업 복지는 기업 정보 탭의 읽기 전용 본문 섹션에 두고, 수정 폼에서는 기업 정보와 개인 기록 사이 장문 입력으로 둔다.
8. 직무의 내용 순서는 담당업무→업무의 영향력→요구 역량→우대 역량→성장 방향→취득 경험이다. 상세와 수정 폼이 같은 순서를 쓴다.
9. 로그인 사용자의 관리자 요청은 우측 하단 고정 버튼으로 연다. 작은 비모달 패널 안에서 최근 요청 목록과 작성·수정·피드백 확인을 처리한다. 관리자는 `/admin`의 탭 안에서 전체 요청과 피드백을 관리한다.

## 컴포넌트

상단 오른쪽 메뉴 버튼은 작은 비모달 사이드 패널을 연다. 패널에 플러그인 연결 가이드와 관리자(ADMIN만)를 둔다. 닫기·Escape·화면 이동 시 닫힌다. 가이드는 기존 라이트 카드·버튼 토큰을 쓰며
URL과 명령 복사 결과는 aria-live로 제공한다. OAuth 내부 설정과 수동 연결 문제 해결 영역은 화면에 두지 않는다. 좁은 화면에서도 URL과 명령을 줄바꿈한다.

| 이름 | 파일 | 비고 |
|---|---|---|
| 세그먼트 | `App.vue` `.segmented` | 라우트 전환 전용 |
| 카드 그리드 | `.card-grid` + `.card` | 기업·공고 공용 |
| 공고 칸반 | `.kanban` `.kanban-column` | 상태별 열. 카드 드래그로 열·탭 사이 이동, 클릭으로 상세 열기 |
| 칩 | `.chip`(중립) `.chip[data-tone]` | 상태·업종·형태 |
| 태그 입력 | `TagInput.vue` `.tag-input` | 기업 업종·직무 기술 스택 공용. 기존 선택 또는 Enter 추가 |
| D-day 배지 | `.dday[data-tone]` | tone 은 `types/posting.ts` 의 `ddayTone()` |
| 드로어 | `Drawer.vue` | props `title`, `subtitle`; `#actions`(헤더 아래) `#default` 슬롯 |
| 종속 행 | `.mini-row` (button) | 더블클릭·Enter 로 그 데이터의 화면을 연다. `user-select: none` |
| 절차 체인 | `.step-chain` `.step-node[data-result]` | `PostingDetail` — 노드 클릭으로 예정↔완료 전환 |
| 가로 스트립 | `.strip` | 직무 드로어의 참고 정보 카드 |
| 기업 자료 앨범 | `.content-grid` | 기업 드로어의 뉴스·유튜브 카드. 작은 화면에서는 한 열 |
| 폼 | `CompanyForm` `PostingForm` | **바깥 껍데기 없음** — 드로어가 감싼다 |
| 첨부 | `AttachmentField.vue` | 값은 첨부 id 문자열 하나. 첨부·교체·제거·미리보기. 파일 input 은 숨기고 버튼이 연다 |
| 행 안의 표 | `TermTable.vue` `.term-table` | 학년별·학기별 이수 내역. 열이 많아 **표만** 가로 스크롤한다 |
| 사업 반복 입력 | `BusinessAreas.vue` `.repeater__row--business` | 기업 주요 사업. 이름 한 줄 + 설명 한 줄 |
| 확인 | `ConfirmDialog.vue` | 파괴적 확인 모달 |
| 관리자 요청 | `AdminRequestWidget.vue` `.request-widget` | 우측 하단 버튼 + 비모달 패널. Escape 닫기, 모바일 좌우 여백 유지 |
| Markdown 메모 | `MarkdownTextarea.vue` + `MarkdownMemo.vue` | 기업·공고·직무 공용. 입력은 Tab 들여쓰기, 상세는 제한 문법만 안전하게 렌더링 |
| 검색 강조 | `.search-highlight`의 `mark` | 자기소개 검색어와 일치한 질문·답변 조각. 사용자 HTML을 쓰지 않음 |

## 실행·검증

```bash
cd frontend && npm run type-check && npm test
docker compose up -d --build && bash scripts/smoke.sh
```

화면은 로그인이 필요해 스모크로 확인할 수 없다. 브라우저에서:
1. 탑바 세그먼트에 `기업`·`채용공고` 둘만 있고 관리자는 따로 떨어져 있는가
2. 카드에 핵심 필드만 있는가
3. 카드 클릭 → 드로어 상세 → `수정` → 같은 드로어에서 저장되는가

## 함정

- **폼 컴포넌트는 스스로 모달을 만들지 않는다.** 드로어 안에 들어가는 것이 전제다. 껍데기를 다시 붙이면 드로어 안에 모달이 겹친다.
- 드로어 폼의 grid 자식과 반복 행 입력은 `min-width: 0`을 유지한다. `datetime-local`의 고유 너비가 520px 드로어를 밀어 가로 스크롤을 만들 수 있다.
- 카드에 필드를 추가하고 싶어지면 상세에 넣는다. 규칙 3이 이 화면의 존재 이유다.
- **드로어는 520px 고정이다.** 폼 한 줄에 넣을 수 있는 건 대략 컨트롤 3개까지다. `datetime-local` 은 한국어 형식(`2026. 09. 10. 오후 06:00`)이라 200px 아래로 내려가면 연도만 남고 잘린다 — 좁아지면 숨기지 말고 줄을 나눈다(`.repeater__when`).
- **`.mini-row` 는 `<div>` 가 아니라 `<button>` 이다.** `<div>` 로 되돌리면 더블클릭이 글자만 선택하고 키보드로는 아예 열 수 없다.
- **이력서 행의 필드는 종류가 늘었다** — `file`·`select`·`terms`. 새 종류를 더하면 `ResumeSection.vue` 의 분기와 `types/resume.ts` 의 `FieldKind`·`MAX_LENGTH` 를 함께 고친다.
- 학력 행은 `schoolType` 에 따라 필드가 **숨는다**(`when`). 숨은 필드의 값은 지워지지 않는다.
- 라이트 테마 하나뿐이다. 다크 토글은 없다 — 요구된 적이 없다.
